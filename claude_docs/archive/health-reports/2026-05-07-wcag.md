# WCAG 2.1 AA Audit — FindA.Sale
**Audit:** #391  
**Session:** S680  
**Date:** 2026-05-07  
**Scope:** Full codebase — organizer + shopper flows (code-level audit). Chrome keyboard/focus testing UNVERIFIED (Chrome MCP unavailable this session).

---

## Summary

Solid color foundation — 89% of color pairings pass WCAG AA and the design system is well-intentioned. However, structural accessibility gaps are widespread: no `<main>` landmark on 90+ pages, 200+ unlabeled inputs, 104+ images missing alt text, and no error identification ARIA on any form. These are systemic gaps from the build phase, not isolated bugs. The good news: most are fixable with targeted sweeps, and the focus indicator system is already correctly implemented.

**Top 3 concerns:** (1) Missing `<main>` landmark sitewide — screen readers can't navigate structure, (2) 200+ unlabeled form inputs — form fields are inaccessible to assistive tech, (3) Ghost button contrast failure in dark mode.

---

## Critical (blocker — fix before #394 Full Walkthrough)

- **Missing `<main>` landmark on 90+ pages** — `packages/frontend/components/Layout.tsx` — Page content is a sibling to nav/footer instead of a child of `<main>`. Screen reader users cannot identify main content area. WCAG 1.3.1 Level A. **Fix: wrap `{children}` in `<main id="main-content">` in Layout.tsx.**
- **Skip link target unconfirmed** — `Layout.tsx:700` — Skip link exists with correct sr-only/focus styling, but its `href` target (`#main-content` or similar) must resolve to the `<main id="main-content">` added above. Currently points nowhere confirmed. WCAG 2.4.1 Level A.

---

## High (fix this week)

- **Ghost button text in dark mode** — `packages/frontend/styles/globals.css:62-65` — `text-[#A8A8AA]` on `#2C2C2E` = 3.6:1 (needs 4.5:1). `text-[#A8A8AA]` on `#1C1C1E` = 3.8:1 (also fails). Fix: increase to `#CACACA` or `#D0D0D0` (~5.1:1). WCAG 1.4.3 Level AA.
- **4 interactive divs without keyboard access** — `BottomTabNav.tsx:194`, `RapidCapture.tsx:1397`, `SaleQRCode.tsx:148`, `pos.tsx:2348` — Divs with `onClick` but no `onKeyDown`, `role`, or `tabIndex`. Not operable via keyboard. WCAG 2.1.1 Level A.
- **Heading skip h1→h3 in organizer dashboard** — `packages/frontend/pages/organizer/dashboard.tsx:773` — Jumps from h1 (line 589) to h3 (line 773) with no h2 in between. WCAG 1.3.1 Level A.

---

## Medium (fix this sprint — accessibility sweep batch)

- **104 `<img>` tags missing alt text** — `PreviewModal.tsx`, `CartDrawer.tsx`, `ItemCard.tsx`, `RapidCapture.tsx`, `PosPaymentQr.tsx`, etc. — Product photos have no accessible description; decorative icons should have `alt=""`. WCAG 1.1.1 Level A.
- **20+ Next.js `<Image>` components missing alt** — `AvatarDropdown.tsx:632`, `CityRecentSales.tsx:79`, `OrganizerSaleCard.tsx:124/140`, `loot-log.tsx:78`, `trending.tsx:89`, etc. WCAG 1.1.1 Level A.
- **200+ inputs without associated labels** — Across every major form component: `CheckoutModal.tsx`, `BidModal.tsx`, `DisputeForm.tsx`, `DonationModal.tsx`, `OnboardingWizard.tsx`, add-items, admin pages, etc. Need `htmlFor`+`<label>` or `aria-label`. WCAG 3.3.2 + 4.1.2 Level A. **Note: This is the largest scope item — recommend dedicated accessibility sprint.**
- **No error identification ARIA on forms** — Only 3 uses of `aria-live`/`role="alert"` sitewide (CookieConsentBanner, NearMissNudge, ToastContext). No `aria-invalid` or `aria-describedby` on any input with error state. WCAG 3.3.1 Level A.

---

## Low (track, fix when relevant)

- **Dark mode secondary text borderline** — `globals.css:183` — `#B8B8BA` on `#2C2C2E` = exactly 4.5:1. Technically passes but zero margin. If background darkens even slightly, it fails. Consider bumping to `#C0C0C2`. WCAG 1.4.3 borderline.
- **Multiple `<nav>` elements without distinguishing labels** — Layout.tsx has 2+ navs. Only 1 has `aria-label`. Screen readers list all navs — duplicate "navigation" landmarks are confusing without labels. WCAG 4.1.2.
