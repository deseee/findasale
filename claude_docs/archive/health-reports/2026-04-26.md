## High (fix this week)

**File:** `packages/backend/.env.example`

The example is missing **12 variables** that exist in the live `.env`:
- `MAILERLITE_API_TOKEN`, `NEXT_PUBLIC_STRIPE_TERMINAL_SIMULATED`
- `STRIPE_BILLING_WEBHOOK_SECRET`, `STRIPE_CONNECT_WEBHOOK_SECRET`
- `STRIPE_GENERIC_ITEM_PRODUCT_ID`, `STRIPE_HUNT_PASS_PRICE_ID`
- And 6 others added since last sync

It also documents **8 variables that no longer exist** in `.env`:
- `AI_COST_CEILING_USD`, `CLOUDINARY_AVG_IMAGE_SIZE_KB`
- `EBAY_DELETION_ENDPOINT_URL`, `EBAY_VERIFICATION_TOKEN`

### H2 — Unimplemented pricing engine adapters returning empty data silently
**Files:** `packages/backend/src/services/pricingEngine/adapters/gsa.ts`, `keepa.ts`, `ebay.ts`

Three pricing engine adapters have `// TODO implement` stubs that return empty arrays or `null`. If the orchestrator calls these, it will silently get no comps data and fall back — without any alert that an adapter is broken. The GSA and Keepa adapters are Phase 1 stubs that have never been implemented.

**Risk:** Price recommendations may be computed from fewer data sources than the UI implies (or than Patrick believes). No error surfacing means this goes undetected indefinitely.

**Fix:** Either implement (if on roadmap) or add an explicit `throw new Error('Not implemented')` / log warning so failures are visible. Low-effort to at least make them loud.

## Medium (fix this sprint)

### M1 — findMany without `take` on public-facing item/sale controllers
**File:** `packages/backend/src/controllers/itemController.ts`, `saleController.ts`

387 total `findMany` calls have no `take` limit across the backend. Most are in admin contexts (acceptable), but several in `itemController.ts` and `saleController.ts` query items or purchases for a sale without pagination caps. A sale with 5,000 items could trigger a full table scan.

**Risk:** Memory spike on large organizer accounts; potential timeout. Not exploitable for data leak (auth-gated), but could cause backend OOM crash or slow responses for heavy users.

**Fix:** Add `take: 500` (or the relevant page size) as a default cap on the most-used public item queries in itemController. Admin queries can remain uncapped as they're intentional.

---

### M2 — Nested `.then()` promise chains without `.catch()` in saleController XP logic
**File:** `packages/backend/src/controllers/saleController.ts` (lines ~786–877)

The sale publish flow has deeply nested `.then()` chains for XP award logic (6 levels deep: organizer → XP check → published count → referral reward → already awarded → award). None of these inner `.then()` calls have a `.catch()`. An unhandled rejection here would silently fail XP awards without any error propagated to the user or logged to Railway.

**Risk:** XP not awarded on sale publish without any user-facing error. Referral rewards could be silently skipped.

**Fix:** Wrap the entire XP promise chain in a try/catch or convert to async/await. Low risk to refactor since it's fire-and-forget post-response.
