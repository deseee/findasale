## High (fix this week)

### H-001: INTERNAL_SCRAPER_KEY — undefined-bypass auth pattern in scraper ingest endpoint
**File:** `packages/backend/src/controllers/internalScraperController.ts` line 17  
**File:** `packages/backend/src/routes/internal.ts` line 153  
**Finding:** The auth guard is `if (key !== process.env.INTERNAL_SCRAPER_KEY)`. If `INTERNAL_SCRAPER_KEY` is not set in the environment, `process.env.INTERNAL_SCRAPER_KEY` evaluates to `undefined`. A request arriving *without* the `x-scraper-key` header sets `key` to `undefined`. The comparison `undefined !== undefined` is `false`, so the guard passes and the request is authenticated. This allows unauthenticated writes to the scraper ingest pipeline.  
**Evidence:** `grep "INTERNAL_SCRAPER_KEY" packages/backend/.env` → no match (key missing from local .env). `grep -n "x-scraper-key" controllers/internalScraperController.ts` → line 17: `if (key !== process.env.INTERNAL_SCRAPER_KEY)`.  
**Production risk:** If `INTERNAL_SCRAPER_KEY` is also absent from Railway env vars (verify in Railway dashboard), the `/api/internal/scraper/ingest` endpoint accepts unauthenticated POST requests with arbitrary scraper payloads. ADR-076 specifies this key must be set in Railway AND as a GitHub Actions secret.  
**Action:** (1) Immediately verify `INTERNAL_SCRAPER_KEY` is set in Railway → Settings → Variables. (2) Fix the guard to explicitly reject when the env var is unset: `if (!process.env.INTERNAL_SCRAPER_KEY || key !== process.env.INTERNAL_SCRAPER_KEY)`. This is a one-line fix that eliminates the bypass regardless of environment.

### H-002: 9 npm HIGH vulnerabilities — ws (runtime socket.io dep) newly elevated
**Packages:** `ws` (two HIGH: uninitialized memory disclosure GHSA-58qx-3vcg-4xpx, memory exhaustion DoS GHSA-96hv-2xvq-fx4p) — transitive via `socket.io` / `engine.io` / `socket.io-adapter`. Plus persisting from prior weeks: `path-to-regexp` (ReDoS, HIGH), `axios` (auth bypass, HIGH), `js-cookie` (HIGH), `esbuild`/`tsx` (dev-only), `semver` (ReDoS).  
**Evidence:** `npm audit --audit-level=high` in `packages/backend` → 42 vulnerabilities (9 HIGH).  
**Context:** `ws` is a runtime dependency via socket.io (used for live presence/bidding). The memory exhaustion DoS vector is exploitable without authentication on the WebSocket upgrade path. `npm audit fix` may resolve the `ws` chain — run and review.  
**Action:** (1) Run `pnpm update socket.io@latest` in backend — check if `ws` chain resolves. (2) Run `pnpm update axios@latest` — resolves the auth bypass. (3) Confirm `js-cookie` is transitive-only (no direct frontend import). (4) Track `path-to-regexp` via Express release notes.

## Medium (fix this sprint)

### M-001: Public AI planner endpoint — no user authentication (cost abuse vector)
**File:** `packages/backend/src/routes/planner.ts` line 20  
**File:** `packages/backend/src/controllers/plannerController.ts`  
**Finding:** `POST /api/planner/chat` is explicitly public with no user auth. It calls Claude (Haiku) and has: (a) rate limiter at 30 req/15min per IP, (b) AI cost ceiling guard (`isAICostCeilingExceeded()` defaults to $50/month when `AI_COST_CEILING_USD` is unset in .env). Mitigations are in place, but a distributed abuse attempt from many IPs could exceed ceiling before the per-IP rate limit triggers. `AI_COST_CEILING_USD` is also missing from local .env (defaults to $50 — may be fine for MVP).  
**Evidence:** `cat routes/planner.ts` → `router.post('/chat', plannerLimiter, ...)` — no `authenticate` middleware. `grep "DEFAULT_CEILING_USD" lib/aiCostTracker.ts` → `const DEFAULT_CEILING_USD = 50`.  
**Action:** For beta phase, current mitigations are acceptable. Before public launch, consider requiring a session token (not full auth, just a CSRF/session cookie) or moving behind soft-auth. Ensure `AI_COST_CEILING_USD` is explicitly set in Railway.
