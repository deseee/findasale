## Medium (fix this sprint)

### M-001: arrivalController — subscribers findMany has no take limit (saleSubscriber)
**File:** `packages/backend/src/controllers/arrivalController.ts` line 167  
**Finding:** `prisma.saleSubscriber.findMany({ where: { saleId } })` has no `take` limit. `recentNotifications` at line 182 was fixed with `take: 2000` — but the subscriber query immediately above it is still unbounded. For a popular organizer with thousands of arrival-alert subscribers, this query scans the full subscriber list on every arrival-notification trigger.  
**Evidence:** `grep -n "take\|findMany" arrivalController.ts` — line 167 has `findMany` with no `take:`, line 194 has `take: 2000`.  
**Action:** Add `take: 500` (or chunked processing) to the `saleSubscriber.findMany` call. Risk is low in beta but grows with scale.

### M-002: 87 unhandled .then() chains in backend controllers
**File:** Multiple controllers  
**Finding:** `grep -rn '\.then\(' controllers/ services/` yields 87 matches without `.catch()` on the same line. Most are likely fire-and-forget (background job triggers, analytics pings) but a subset may silently swallow errors on critical paths.  
**Evidence:** Count confirmed via grep — 87 occurrences.  
**Action:** Sweep controllers/ for `.then()` chains on non-background operations (email sends, Stripe calls, DB writes) and add `.catch(err => logger.error(...))`. Not urgent but creates silent failure surface.

### M-003: pricing.ts TODO — "Verify middleware exists" comment
**File:** `packages/backend/src/routes/pricing.ts` line 12  
**Finding:** Comment reads `// TODO: Verify middleware exists`. `requireOrganizer` is imported from `../middleware/auth` — the middleware does exist. This is a stale concern comment that could mislead a future dev.  
**Evidence:** `grep -n "requireOrganizer" routes/pricing.ts` — imported and used; middleware confirmed present in `middleware/auth.ts`.  
**Action:** Remove the TODO comment. One-liner fix.

### L-001: 78 buttons without explicit aria-label
**File:** Various pages and components  
**Finding:** Grep for `<button>` tags without `aria-label`, `aria-labelledby`, or `title=` yields 78 hits. Review indicates most are labeled buttons with visible text children (not icon-only), so screen readers read the text content directly. However, a subset (especially icon-only action buttons in tables and toolbars) would benefit from explicit labels.  
**Evidence:** `grep -rn '<button[^>]*>'` without aria attributes = 78 occurrences.  
**Action:** Spot-check icon-only buttons (edit/delete/close icons in item tables and modals). Add `aria-label` to any button whose visible content is only an SVG icon.
