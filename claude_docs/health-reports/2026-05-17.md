## High (fix this week)

### H-001 — Two unauthenticated internal endpoints (Auth Gap)

**File:** `packages/backend/src/routes/internal.ts`

**Finding 1:** `POST /api/internal/category-sync/trigger` has no middleware and no in-controller auth check. Any external caller knowing the URL can trigger a full eBay category sync job, causing Railway CPU/memory spikes and potential eBay API quota burn.
```ts
// Line ~852 — missing requireSecret:
router.post('/category-sync/trigger', async (req, res) => {
  await runCategorySync(); // no auth check
```

**Finding 2:** `POST /api/internal/scraper/ingest` uses its own `x-scraper-key` / `INTERNAL_SCRAPER_KEY` check inside the controller, while all other routes use the `requireSecret` middleware (`OUTREACH_SECRET`). Two separate internal auth key systems creates operational risk — if one is rotated without the other, routes silently become unprotected.

**Action:** Add `requireSecret` to `category-sync/trigger`. Consolidate the two internal key systems or add explicit documentation that they are intentionally separate.

### H-002 — Voice input overwrites organizer-set price (Organizer Intent Rule Violation) [CARRY-OVER]

**File:** `packages/frontend/pages/organizer/add-items/[saleId].tsx:1402`
**Still present — not fixed since 2026-05-10 report.**

```ts
price: estimatedPrice ? estimatedPrice.toString() : prev.price,
```

This replaces any organizer-entered price with the AI estimate whenever `estimatedPrice` is truthy. The correct fix (add `&& !prev.price` guard) is a single-line change. Dispatch to `findasale-dev`.


### M-003 — Inconsistent internal auth key scheme
**File:** `packages/backend/src/routes/internal.ts`

Two parallel auth systems exist on the same `/api/internal/` prefix:
- `requireSecret` middleware → checks `OUTREACH_SECRET` env var
- `ingestFromGitHubActions` controller → checks `INTERNAL_SCRAPER_KEY` env var

This is documented nowhere and creates confusion for future route additions (which key should a new route use?). Risk: a new route added using the wrong middleware is authenticated but with the wrong key, giving GitHub Actions access to admin operations or vice versa.

**Action:** Add a comment block at the top of `internal.ts` explaining the two-key scheme and when each applies. Or consolidate to a single `INTERNAL_API_KEY`.
