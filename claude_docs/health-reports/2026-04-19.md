## High (fix this week)

### H-001 — aiSuggestedPrice overrides organizer price in `getComps` and `getEbayPreview`

**File:** `packages/backend/src/controllers/ebayController.ts`  
**Lines:** 460–468 (`getComps`), 1469–1477 (`getEbayPreview`)  
**Root cause:** Two price determination blocks still use the old ordering: `aiSuggestedPrice > estimatedValue > price`. The bulk listing path was corrected on 2026-04-14 (line 1746) with the comment "organizer-set price always wins" but the other two paths were not updated.

**Current broken order (lines 462, 1472):**
```
aiSuggestedPrice → estimatedValue → item.price → 0.99
```

**Correct order (line 1748, already fixed):**
```
item.price → aiSuggestedPrice → estimatedValue → 0.99
```

**Impact:** An organizer who sets a price of $285 will have eBay listings sent at the AI-suggested price instead — the exact incident that triggered the 2026-04-14 fix. `getComps` is the pricing comps endpoint; `getEbayPreview` previews the listing before publishing. Both affect organizer trust.

**Fix:** Apply the same pattern as lines 1747–1753 to the `getComps` block (lines 461–469) and `getEbayPreview` block (lines 1470–1478). Three-line change per block.

## Medium (fix this sprint)

### M-001 — Unbounded `bid.findMany` on auction item detail (`getItemBids`)

**File:** `packages/backend/src/controllers/itemController.ts` line 947  
**Issue:** Fetches ALL bids for an auction item with no `take` limit. For a popular item with 200+ bids this returns the full set on every page load. Low risk now at beta scale; becomes a perf problem at volume.  
**Fix:** Add `take: 100` (or paginate). Bid history rarely needs more than the most recent 50–100.

### M-002 — Unbounded `review.findMany` on sale detail page

**File:** `packages/backend/src/controllers/saleController.ts` line 366  
**Issue:** Fetches ALL reviews for an organizer (across all their sales) to compute `avgRating`. An organizer with 500 sales could have 5,000+ reviews returned just to compute a single average.  
**Fix:** Use `prisma.review.aggregate({ _avg: { rating: true }, where: { sale: { organizerId: ... } } })` — computes the average in SQL with no row transfer overhead.

### M-003 — `(prisma as any)` cast in `getSalesByNeighborhood`

**File:** `packages/backend/src/controllers/saleController.ts` line 860  
**Issue:** `(prisma as any).sale.findMany(...)` bypasses TypeScript type checking. Likely a workaround added when `neighborhood` field was added to the schema before the Prisma client was regenerated. The `take: 50` limit and `select` scope are correct — this is a type safety gap, not a data risk.  
**Fix:** Remove the `as any` cast. Run `npx prisma generate` if the field is now in schema — the cast should no longer be needed.
