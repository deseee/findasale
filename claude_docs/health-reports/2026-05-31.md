## High (fix this week)

### H-001: STRIPE_CONNECT_WEBHOOK_SECRET is a placeholder in local .env
**File:** `packages/backend/.env` line 10  
**Finding:** Value is `[PLACEHOLDER — See instructions below]` — a literal string. The backend code reads this via `process.env.STRIPE_CONNECT_WEBHOOK_SECRET`. The good news: the code handles this gracefully (the connect webhook signature verification is attempted only when `connectSecret` is truthy after a platform-secret failure). However, if this value were passed to Railway, all Stripe Connect webhook events (POS payments, connected account events) would fail signature verification silently.  
**Action:** Verify that `STRIPE_CONNECT_WEBHOOK_SECRET` in Railway's production environment has the real Stripe webhook signing secret (from Stripe Dashboard → Webhooks → Connected account webhook endpoint). Local `.env` can stay as-is since it's gitignored.

### H-002: Env vars in .env.example missing from .env — verify in Railway
**Files:** `packages/backend/.env` vs `.env.example`  
The following vars are documented in `.env.example` but absent from local `.env`. Some may be intentionally omitted locally but must be present in Railway production:

| Variable | Risk if missing in Railway |
|---|---|
| `OUTREACH_SECRET` | Outreach cron job throws and aborts (`OUTREACH_SECRET env var is required`) — outreach emails stop |
| `INTERNAL_SCRAPER_KEY` | All internal geocoding and scraper routes return 401 — scraper pipeline silently breaks |
| `EBAY_VERIFICATION_TOKEN` / `EBAY_DELETION_ENDPOINT_URL` | eBay marketplace account deletion requests fail — potential eBay compliance issue |
| `GOOGLE_PLACES_API_KEY` | Address verification/Places lookups fail silently (likely intentionally absent per Google billing lockdown May 2026) |
| `MAILERLITE_SHOPPERS_GROUP_ID` | Shopper MailerLite group assignment would fail |
| `AI_COST_CEILING_USD` | AI cost ceiling guard may default to unlimited |
| `INDEX_NOW_KEY` | IndexNow ping for SEO would be skipped |
| `RATE_LIMIT_WHITELIST_IPS` | No whitelist applied to rate limiter |

**Action:** Open Railway dashboard → backend service → Variables and confirm `OUTREACH_SECRET`, `INTERNAL_SCRAPER_KEY`, `EBAY_VERIFICATION_TOKEN`, and `EBAY_DELETION_ENDPOINT_URL` are set. The Google Places lockdown is documented as intentional.

## Medium (fix this sprint)

### M-001: SaleTypeBadge.tsx has stale TODO comments — fields are in schema
**File:** `packages/frontend/components/SaleTypeBadge.tsx` lines 7, 8, 110, 122, 124  
**Finding:** Comments and TODOs say "saleSubtype not in schema" and "isOnlineOnly not in schema." Both fields **are** in `packages/database/prisma/schema.prisma` (lines 804–805) and have been for some time. The component correctly accepts them as props, so there's no bug, but the comments are misleading for any dev reading this file.  
**Action:** Remove the stale TODO comments. Update the file header note to say "fields are in schema as of [migration date]."

### M-002: arrivalController subscriber findMany — no take limit
**File:** `packages/backend/src/controllers/arrivalController.ts` lines 167, 182  
**Finding:** `prisma.saleSubscriber.findMany` and `prisma.pushNotificationLog.findMany` fetch all records for a `saleId` with no `take` limit. For large sales (popular organizer with thousands of subscribers), this could be a slow query at scale.  
**Current risk:** Low in beta with small user count. Elevated risk at scale.  
**Action:** Add `take: 1000` or cursor-based pagination. For notification dispatch, process in chunks of 100.

### M-003: bountyController getCommunityBounties — take limit present but check max
**File:** `packages/backend/src/controllers/bountyController.ts` lines 267+  
**Finding:** `getCommunityBounties` uses `take: limitNum` which is good — but verify `limitNum` has a server-side maximum cap (e.g., `Math.min(limitNum, 100)`). No max cap visible in the snippet.  
**Action:** Verify `limitNum` is capped server-side.

### M-004: pricing.ts TODO comment is stale  
**File:** `packages/backend/src/routes/pricing.ts` line 12  
**Finding:** Comment says `// TODO: Verify middleware exists`. The middleware (`requireOrganizer` in `middleware/auth.ts` line 66) exists and is correctly applied to all pricing routes.  
**Action:** Remove the TODO comment.

### L-003: message-templates.tsx input missing aria-label
**File:** `packages/frontend/pages/organizer/message-templates.tsx` line 97  
**Finding:** `<input type="text">` for template title has no `aria-label`. The field is inside a form with visible surrounding context but screen readers may not associate the label.  
**Action:** Add `aria-label="Template title"` to the input.

### L-004: 3 unbounded admin findMany calls — acceptable for admin context
**Files:** `adminBroadcastController.ts`, `adminController.ts`, `adminAffiliateController.ts`  
**Finding:** Several `findMany` calls without `take` limits fetch users or purchases for admin reporting. These are admin-only routes (`router.use(authenticate, requireAdmin)`), so they are not exploitable by regular users. At production scale they could be slow but are not a security issue.  
**Action:** Revisit if admin panel becomes slow. Consider adding `take: 5000` safety caps.
