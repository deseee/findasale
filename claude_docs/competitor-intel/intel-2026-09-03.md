## Tech Signals

**Next.js version gap has escalated — now confirmed exposed to a second, more severe CVE class.** Direct grep this cycle (`grep -n '"next"' packages/frontend/package.json`) confirms the pin is still `"next": "^15.5.20"`. Since last cycle's flag (15.5.20 vs. the then-current patched 15.5.21), Next.js has shipped a further patch: **v15.5.24, released August 25, 2026**, fixing a vulnerability in the `sharp`/`libheif` image-processing library that can lead to **unauthenticated remote code execution** when Next.js Image Optimization processes an attacker-controlled AVIF image. FindA.Sale is a photo-upload-centric app (organizer cataloging workflow is the core product loop) — if `next/image` optimization is in the request path for any user-uploaded photo, this is now a directly relevant RCE surface, not just a generic "stay current" hygiene item. This is the sixth consecutive cycle this pin has gone unaddressed (07-23, 07-30, 08-06, 08-13, 08-27, 09-03) and the underlying risk has gotten materially worse, not just older. Per the project's own age-based severity floor this was already P1-minimum after 5 cycles; the new RCE-via-image-optimization detail plus FindA.Sale's photo-upload-heavy workflow argues for treating this as P0 and dispatching a version bump + AVIF/Image-Optimization exposure check directly rather than re-flagging a seventh time. [August 2026 Security Release | Next.js](https://nextjs.org/blog/august-2026-security-release), [Next.js Security Advisories](https://nextjs.org/blog/tag/security)
