**Scope:** Scrutiny of S657–S665 audit work (Fortune 1000 sweep, outreach hardening, sitewide pre-launch, image proxy). Find what was missed within stated scope, what was never audited, what was rubber-stamped, what cross-cutting concerns no single-domain audit could see.

## Executive summary

S657–S665 shipped a lot of code. Verification quality is uneven. Three structural risks dominate:

1. **Migration deploy is unconfirmed.** S664's `20260506000001_add_age_verified` (adds `ageVerifiedAt`, `stripeOnboarded`, `ProcessedWebhookEvent`) is listed as "Patrick action required" — there is no evidence Railway ever ran it. If false-confirmed, every Stripe webhook write to `ProcessedWebhookEvent` 500s in production.
2. **The audits ran along compliance vectors, not adversary vectors.** Auth/WCAG/Legal/SEO/Payments/Reliability is a checklist of *categories*. Nothing audited multi-tenant data isolation (IDOR), race conditions, cron failure observability, or scraper ToS compliance — areas where one bug = catastrophic.
3. **Rubber-stamp pattern is recurring.** S664 claims "all 34 modals focus-trapped" but the evidence is "AccessibleModal wrapper applied" — no Tab cycle, no Esc behavior, no focus restoration tested. Same shape as S285–S289 fabrications that triggered the QA Honesty Gate.

**28 distinct gaps identified.** 5 P0, 14 P1, 7 P2, 2 P3.

## Section 2 — Coverage gaps INSIDE S664's stated scope

S664 ran six audits. Within each declared scope, the agent found sub-areas that were not examined. Top items per domain:

**Auth/Security**
- OAuth users (Google/Facebook signup) skip the age gate entirely — DOB check is on POST /register only. COPPA risk for OAuth path. (P1)
- Password change increments `tokenVersion` but doesn't `clearCookie('refreshToken')` — old refresh token continues issuing access tokens until natural expiry. (P1)
- `POST /reset-password` has no per-token attempt rate limit. `forgotPasswordLimiter` gates email sending only; once a token is issued it can be guessed without throttle. (P2)
- Account enumeration on `/verify-email` resend (no rate limit; success/already-verified messages differ). (P2)

**Accessibility/WCAG**
- No aria-live region for form validation errors — screen readers won't announce failed search/filter submissions. (P1)
- No skip-to-content link audit (WCAG 2.4.1). (P1)
- Heading hierarchy not verified across dynamic pages (sales, items, organizer profiles). (P2)
- `prefers-reduced-motion` not respected — modals, countdowns, carousels animate regardless. (P2)
- Image alt text on dynamic item photos not systematically audited. (P1)

**Legal/Compliance**
- GDPR Article 20 (data portability/export) not implemented. Account deletion shipped without first letting user download their data. (P1)
- CCPA "Do Not Sell My Personal Information" link not in cookie consent banner. (P1)
- CAN-SPAM physical-address placeholder rendering not verified — outreach emails may literally contain `[physical address]` if env var substitution fails. (P2)
- 1099-K threshold tracking absent (organizer hits $20k + 200 transactions → IRS reporting required, no internal alert). (P2)
- ToS arbitration clause absent — class-action exposure if litigation arises. (P2)

**SEO/Performance**
- Canonical URLs only on items/[id] (line 466). Missing on sales/[id], organizers/[id], categories, neighborhoods, search. (P1)
- Open Graph/Twitter cards inconsistent across shareable surfaces. (P2)
- Sitemap completeness vs. actual indexable routes never reconciled. (P2)
- Homepage has ISR but no Organization+SearchAction JSON-LD (✅ confirmed live by V-probe — this one is fine). 
- hreflang absent (low priority, US-only for now). (P3)

**Payments/Stripe**
- Subscription dunning / failed-renewal retry policy not documented or audited. PRO/TEAMS are subscriptions; S664 audit covered one-time only. (P1)
- `charge.refunded` webhook not handled — refund initiated from Stripe Dashboard (not FindA.Sale) leaves DB out of sync. (P2)
- Tax: no Stripe Tax integration, no per-state sales tax logic. Mixed-state carts compound risk. (P1)
- Tier-end-date display vs Stripe `grace_period` mismatch — UI may show wrong expiry during dunning. (P2)

**Backend Reliability**
- Cron failure alerting absent. (See V5 — P0.)
- Prisma connection pool not monitored; no slow-query alerting. (P2)
- No SIGTERM/graceful shutdown handler — Railway redeploy mid-webhook can drop or duplicate. (P2)
- Background-job retry/dead-letter queue absent — at scraper scale, irrelevant; at 10k+ outreach scale, real. (P2)
- Webhook event pruning job (`webhookEventPruneJob.ts`) wired but no failure alert if pruning breaks → table grows unbounded. (P2)
- Redis cache eviction policy under memory pressure unclear — rate limiter degrades silently. (P2)
