### Issues Found

#### HIGH

- **Double `/api/` prefix on points visit-tracking call** — `sales/[id].tsx:304` — high
  `api.post('/api/points/track-visit', ...)` resolves to `/api/api/points/track-visit` because the axios instance already has `baseURL: '/api'`. Every other call in the file omits the prefix (e.g. `/sales/${id}/visit`, `/streaks/visit`). Points are never awarded for sale page visits. Fix: change path to `/points/track-visit`.

- **Remove-photo button permanently invisible on thumbnail strip** — `sales/[id].tsx:1252` — high
  The button has `opacity-0 group-hover:opacity-100` but its parent `div` (line 1241) is missing the `group` Tailwind class. The hover state never fires. Organizers cannot use the thumbnail strip to remove photos. Fix: add `group` to the parent div's className.

#### MEDIUM

- **Tag filter chips: unselected text is near-black `#1A1814` in dark mode** — `sales/[id].tsx:1606–1618` — medium
  Unselected tag buttons use inline `color: '#1A1814'` (dark charcoal) which is invisible against the dark page background (`#0B0F17`). The class `dark:border-white/14` is applied but no dark-mode text override exists. Affects sales that have tags populated. Fix: add `'#F2F0EA'` to the non-selected color branch when in dark mode, or use Tailwind classes instead of inline styles.

- **Leave-warning `beforeunload` handler fires async — never blocks native nav** — `sales/[id].tsx:329–338` — medium
  The `beforeunload` event calls `api.get('/reservations/shopper')` asynchronously. Browser unload events are synchronous; the response is discarded before it resolves. A shopper closing the tab with active holds will bypass the warning. The Next.js `router.events` path (line 341–360) works correctly for SPA navigation, so this only affects hard closes/refreshes. Fix: pre-fetch hold state and cache it, then check the cache synchronously in the handler.

- **Sale date rows show `h:mm a` time when dates are likely date-only** — `sales/[id].tsx:1388` — medium
  `format(parseISO(day.date), 'h:mm a')` renders a time column next to each sale day. If `startDate`/`endDate` are stored without a time component (or UTC midnight), every row shows `12:00 AM`. This is confusing for shoppers. Fix: only show the time column if the stored time is not midnight, or remove it from the date-row display (time info isn't shown elsewhere on the page either).

- **`rarity` field accessed via `(item as any).rarity` — field not in Item interface** — `sales/[id].tsx:1744` — medium
  The rarity badge conditional checks `item.listingType && ['RARE','ULTRA_RARE','LEGENDARY'].includes((item as any).rarity)` but `rarity` is not defined in the `Sale.items` interface (lines 102–123). If the API returns this field it works; if not, badges silently never render. Fix: add `rarity?: string | null` to the item interface so the type contract matches what the API sends.

#### LOW

- **`ActivityFeed` imported but never rendered** — `sales/[id].tsx:48` — low
  Line 48 imports `ActivityFeed` from `../../components/ActivityFeed` but it does not appear anywhere in the JSX. Dead import. Fix: remove the import or wire the component.

- **`initialSalesData` fetched in `getStaticProps` but never consumed** — `index.tsx:655–668` — low
  `getStaticProps` returns `initialSalesData` and the ISR 5-min cache is set up, but the component's `useQuery` always runs a fresh client-side fetch regardless. The prop is accepted in the interface but ignored. Either wire it as `initialData` on the query or remove the SSR fetch.

- **Loading skeleton for sale detail includes an empty unstyled card** — `sales/[id].tsx:617` — low
  `<div className="bg-white dark:bg-gray-800 rounded-lg shadow-md p-6 mb-8"></div>` renders a blank card with shadow but no skeleton content. It appears as a ghost box mid-page. Fix: wrap its interior in `<Skeleton>` children or remove it.

- **Map section collapses entirely during loading (no placeholder)** — `index.tsx:429` — low
  The map container is gated on `!isLoading && hasMapPins`, so on first load the map area disappears completely. The card footer shows a skeleton but the map space shows nothing. A fixed-height placeholder or skeleton would prevent layout shift.

- **`console.error` calls in production code** — `index.tsx:134, 199` / `sales/[id].tsx:437` — low
  Several non-fatal error branches log to console in production. Not user-facing but pollutes browser dev tools and may leak error details. Fix: strip or replace with silent no-ops.
