# UX Spot-Check — 2026-05-20

### Issues Found

#### HIGH (2)

- **Literal "X" placeholder in live JSX** — `dashboard.tsx` ~line 1366 — Text reads `"X shoppers have questions — answer them"` with a literal capital X instead of the actual `viewCount` or message count value. This is visible to real users when `statsData.activeSale.viewCount > 10`. — **high**

- **Rules of Hooks violation — early return before useQuery** — `edit-sale/[id].tsx` ~line 105–110 — An early return (`router.push('/login'); return null`) fires before the `useQuery` call. Hooks must not be called conditionally; any early return before a hook invocation breaks React's rules, causes runtime warnings, and can produce hydration mismatches. — **high**

#### MEDIUM (7)

- **Secondary dashboard queries have no loading/error handling** — `dashboard.tsx` ~lines 186–416 — `analyticsData`, `orgProfile`, `storefrontSlug`, `earnings`, `holdCountData`, `statsData`, and `tierData` queries are unguarded. While `salesLoading` triggers the main skeleton, these queries silently render `undefined` or nothing while fetching. — **medium** (×6 queries)

- **Clipboard copy with no error handler** — `dashboard.tsx` ~line 888–891 — The "Copy Link" button inside the Storefront Widget calls `navigator.clipboard.writeText()` with no try/catch. If clipboard access is denied, the button silently fails. The equivalent copy button at ~line 1183 correctly wraps in try/catch with a toast fallback. — **medium**

- **Geocoding failure swallowed silently** — `edit-sale/[id].tsx` ~line 147 — When auto-geocoding on load fails, the error is caught and only logged (`console.error`). No toast is shown to the user. They are dropped into the fallback UI with no explanation that geocoding was attempted and failed. — **medium**

#### LOW (8)

- **`console.error` calls in production pages** — `dashboard.tsx` ~lines 386, 1157, 1708; `edit-sale/[id].tsx` ~line 394 — Should be removed or replaced with Sentry/monitoring. — **low**

- **Inconsistent empty-state check — Past Sales section** — `dashboard.tsx` ~line 1684–1687 — State 3 (all sales ended) iterates `salesData.map()` unconditionally. If `salesData` is empty after the state check, the section renders a heading over an empty container with no "no past sales" message. — **low**

- **Geocoding spinner has no visual indicator component** — `edit-sale/[id].tsx` — When `isAutoGeocodingOnLoad` is true, only text ("Finding location coordinates…") is shown; no spinner/activity indicator component accompanies it. — **low**

- **`sale.items` existence not guarded before length check** — `edit-sale/[id].tsx` ~line 485 — "No items yet" banner checks `sale.items && sale.items.length === 0`. If the API response omits `items`, the banner silently disappears. — **low**

- **Redundant `aria-label` where `htmlFor`/`id` already exist** — `edit-sale/[id].tsx` ~lines 601–1043 — Multiple inputs carry both a correct `<label htmlFor="...">` and a redundant `aria-label`. When a proper label association already exists, `aria-label` is redundant and may cause double-announcement in some screen readers. Affects: title, address, city, state, zip, startDate, endDate, neighborhood, markdownFloor inputs. — **low**

- **Icon-only links missing `aria-label`** — `dashboard.tsx` ~line 1055–1058 — Two icon-only `<Link>` elements (Pencil and Eye icons) on the active sale card use `title=` (tooltip) but no `aria-label`. `title` is not reliably read by all screen readers. — **low**

- **Dropdown buttons missing ARIA attributes** — `dashboard.tsx` ~lines 673–722 — The "Add Items" and POS dropdown trigger buttons have no `aria-label`, `aria-expanded`, or `aria-haspopup` attributes. — **low**

- **"Generate Description" button gives no tooltip when disabled** — `edit-sale/[id].tsx` ~line 307 — Button is correctly disabled when title is empty but provides no tooltip explaining why it's inactive. Users may be confused. — **low**
