# UX Spot-Check — 2026-05-13
## Flow: Organizer — Create Sale + Add Items
## Files Reviewed:
- `packages/frontend/pages/organizer/create-sale.tsx` (2,381 lines)
- `packages/frontend/pages/organizer/add-items/[saleId].tsx` (2,862 lines)

---

### Issues Found

- **`isOnlineOnly` value silently discarded on publish** — `create-sale.tsx:2147` — **severity: high**
  The "Online Only — No physical address" toggle in Step 2 of the create-sale wizard correctly updates `form.isOnlineOnly` and conditionally hides address fields in the UI, but `buildPayload()` never includes `isOnlineOnly` in the API payload sent to the backend. The Prisma schema field (`isOnlineOnly Boolean @default(false)`, schema line 751) has existed for some time. When an organizer selects Online Only, the sale is saved to the database with `isOnlineOnly = false` — address validation is bypassed in the UI but the backend record is incorrect. The stale comment at line 8 (`TODO: schema field`) is misleading — the schema field is there, the bug is purely in buildPayload. Fix: add `isOnlineOnly: form.isOnlineOnly` to the returned object in `buildPayload()`.

- **Photo reorder/remove buttons lack accessible labels** — `create-sale.tsx:1232, 1243, 1253` — **severity: low**
  The move-left (`←`), move-right (`→`), and remove (`×`) buttons on photo thumbnails in Step 3 use arrow/cross characters with no `aria-label`. Screen readers will announce these as raw Unicode characters. The add-items page handles this correctly (line 1528: `aria-label="Remove photo N"`). Fix: add `aria-label="Move photo left"`, `aria-label="Move photo right"`, and `aria-label="Remove photo"` respectively.

- **"Enhancement coming soon" toast is user-visible placeholder text** — `add-items/[saleId].tsx:1949` — **severity: low**
  The `onEnhanceAll` callback shows `showToast('Enhancement coming soon', 'info')`. The comment confirms this is a stub (`BUG 6 FIX: Show placeholder since no backend endpoint exists yet`). This is exposed to organizers as a clickable action that leads to a toast announcing the product is incomplete. The button should either be hidden (conditional render on a feature flag) or removed from the UI until the endpoint ships.

- **Multiple `console.error` calls in production render path** — `add-items/[saleId].tsx:763, 1085, 1091, 1149, 1203, 1239, 1291, 1345, 1388` — **severity: low**
  Nine `console.error` statements across upload, AI polling, voice extraction, and bounty matching paths. All are in catch blocks for non-critical flows (silently failing is the intent), but they leak internal service names and error shapes to browser DevTools. Low functional risk but a noise/info-leakage concern for beta users with DevTools open. Could be removed or wrapped in a dev-only logger.

### Clean

- **Auth guards correctly positioned** — Both files place early-return auth redirects AFTER all hook declarations, avoiding Rules of Hooks violations. `create-sale.tsx` uses a `useEffect` pattern; `add-items` uses a post-hooks conditional return with `router.push`. Both are correct.
- **SSR safety** — All `window.*`, `document.*`, and `localStorage.*` accesses are guarded. `create-sale.tsx` uses `typeof window !== 'undefined'` in the `useState` initializer for draft restore, `isClient` state with a `useEffect(() => setIsClient(true))` pattern, and `useEffect` for MutationObserver. `add-items` wraps all window access in useEffect or event handlers. The eBay/QuickBooks CSV download pattern (`document.createElement('a')`) runs only in async user-triggered handlers — safe.
- **Loading states** — Both files handle loading well. `create-sale.tsx` shows uploading state on the photo button (`⏳` / `Uploading…`). `add-items` imports and uses `<Skeleton>` components at appropriate data-pending points (lines 1414–1417, 1981–1983), and tracks `photoUploading` state with visible feedback.
- **Error states** — API failures are caught and surfaced via `showToast('...', 'error')` throughout. Tier limit errors in `create-sale.tsx` display a dedicated inline modal with upgrade CTA. Bulk operation errors in `add-items` use `BulkOperationErrorModal`.
- **Empty states** — Both handled. `create-sale.tsx` Step 3 (photos) shows "Skip photos →" with warning text "Sales without photos get far fewer views" when `photoUrls.length === 0`. `add-items` shows a contextual empty state at line 1472 with description and CTA. Item list shows "No items added yet" at line 2335.
- **Image alt text** — All `<img>` tags have alt text. `create-sale.tsx` photo thumbnails use `alt={\`Photo ${idx + 1}\`}`. `add-items` item list uses `alt={item.title}`.
- **No `console.log` or `alert()`** — Neither file contains any `console.log` or `alert()` calls.
- **Hardcoded placeholders** — No user-visible "Coming soon", "lorem ipsum", or "TODO" text in rendered JSX, except the `onEnhanceAll` toast noted above.
- **`isOnlineOnly` UI logic** — The toggle correctly conditionally renders the address section (`!form.isOnlineOnly`) and shows an "Online Only" notice in its place. Validation at line 2101 also skips address validation when `isOnlineOnly` is true. The UI-side logic is complete; only the payload transmission is missing.
