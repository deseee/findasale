## Issues Found

### line-queue/[id].tsx

- **Rules of Hooks violation — `useCallback` and `useEffect` declared after a conditional `return null`** — `line-queue/[id].tsx:56–71` — **severity: high**
  The auth guard at line 56 (`if (!authLoading && ...) { router.push('/login'); return null; }`) fires after all `useState` calls but BEFORE `useCallback` (line 59) and `useEffect` (line 71). On first render `authLoading` is true so all hooks run; on a subsequent render where a non-organizer is detected, the component returns early and those two hooks are NOT called. React will throw "Rendered fewer hooks than expected" for non-organizer visitors once auth resolves. Fix: move the auth guard to after all hook declarations, or use `useEffect` for the redirect.

- **Initial load failure shows misleading empty state** — `line-queue/[id].tsx:59–70` — **severity: medium**
  `loadStatus` silently swallows all errors in the catch block. On the initial fetch, if the API fails, `isLoading` is set to `false` via `finally` while `entries` stays `[]`. The user sees "🏁 No one in line yet." when the truth is "the data couldn't be loaded." Subsequent polls also fail silently with no staleness indicator. Fix: distinguish first-load errors from poll errors; show an error message on initial failure.

- **Silent poll failure — no staleness indicator** — `line-queue/[id].tsx:65` — **severity: low**
  Background polls fail with `// Silently ignore poll errors`. If the API goes down mid-session, the organizer sees stale data with no visual indication. A last-updated timestamp or a subtle "⚠ Not updating" badge would address this.

- **"Entered ✓" button lacks `aria-label`** — `line-queue/[id].tsx:~175` — **severity: low**
  The "Entered ✓" per-row button renders icon text only (`Entered ✓`) with no `aria-label`. Screen readers will read the emoji as "white heavy check mark". Add `aria-label={`Mark ${entry.user.name} as entered`}`.

### shopper/dashboard.tsx

- **Pickups tab renders blank screen** — `shopper/dashboard.tsx` — **severity: high**
  The tab strip includes a "Pickups" tab (`{ id: 'pickups', label: 'Pickups' }`), and the component tracks `activeTab === 'pickups'` in state, hash routing, and type definitions — but there is no corresponding `{activeTab === 'pickups' && ...}` JSX render block. Clicking Pickups produces a completely empty content area. The `MyPickupAppointments` component is imported (line 32) but never rendered. Fix: add the Pickups tab content block using `<MyPickupAppointments />`.

- **`alert()` used for clipboard copy confirmation** — `shopper/dashboard.tsx:149` — **severity: medium**
  `handleCopyReferralLink` calls native `alert('Referral link copied to clipboard!')` on successful clipboard write. This blocks the browser UI, is out of brand, and is jarring on mobile. `useToast` is already available in most dashboard components — swap for `showToast('Referral link copied!', 'success')`. (Note: `useToast` is not imported in this file and would need to be added.)

- **`console.error` in production code** — `shopper/dashboard.tsx:112, 129` — **severity: low**
  Two `console.error` calls remain in the referral code and QR code fetch `catch` blocks. Silent failure is fine for these enhancement fetches, but `console.error` pollutes the browser console in production and may surface to error monitoring tools. Remove or replace with a no-op.

- **Dead code / deferred TODO not wired** — `shopper/dashboard.tsx:~197` — **severity: low**
  `const hasSavedItems = false; // TODO: wire to collection API when available` — this variable is declared but never used in any conditional or render. Either wire it or remove it.

- **Tab buttons lack ARIA roles** — `shopper/dashboard.tsx:~450–470` — **severity: low**
  The tab row renders plain `<button>` elements without `role="tab"`, `aria-selected`, or a wrapping `role="tablist"`. Assistive technology won't identify these as a tab group. The associated content panels also lack `role="tabpanel"`. This is a recurring pattern in the dashboard that should be addressed globally.
