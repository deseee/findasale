### Issues Found

#### index.tsx

- **No error state for failed search query** — `pages/index.tsx:135`. The `useQuery` for search omits `isError` from its destructure. If the `/search` API call fails while `searchQuery.length >= 2`, the user sees "0 results for X" with no indication that an error occurred. A search network failure silently presents as an empty result set. — **severity: medium**

- **"Save This Search" button visible to unauthenticated users** — `pages/index.tsx:329`. The button renders whenever `searchQuery` is non-empty, with no `user` guard. An unauthenticated user who types a search will see the save button, click it, and receive a generic "Failed to save search" toast. Should either be hidden (`user && searchQuery && ...`) or redirect to login. — **severity: medium**

- **Search input missing accessible label** — `pages/index.tsx:321`. The search `<input>` has `placeholder` text but no `aria-label` attribute and no associated `<label>` element. Screen readers announce this field as unlabeled. Add `aria-label="Search sales by title, city, or keyword"`. — **severity: medium**

- **Date filter buttons missing `aria-pressed`** — `pages/index.tsx:401`. The "All / Upcoming / This Weekend / This Month" toggle buttons change visual state via `className` but don't set `aria-pressed`. Screen readers cannot convey the active filter state. — **severity: low**

- **Map renders 220px empty container when sales have no coordinates** — `pages/index.tsx:354`. The map section is gated on `sales.length > 0` but not on whether any sales have valid lat/lng. If all sales are missing coordinates, `pins=[]` renders a 220px blank map container with no feedback. — **severity: low**

#### sales/[id].tsx

- **OG meta double-render when SSR ogData present** — `pages/sales/[id].tsx:630`. When `ogHead` is truthy (SSR path), the page renders the `ogHead` constant at top AND then inside the main `return` renders `saleForOGMeta && <SaleOGMeta ...>` again via the `{ogHead ? ... : ...}` conditional — the truthy branch renders a second `SaleOGMeta`. Two OG meta blocks in the document head simultaneously. Social scrapers may pick up conflicting tags. — **severity: medium**

- **Buyer's Premium disclosure misplaced for auction sales** — `pages/sales/[id].tsx:973`. The buyer's premium callout renders inside the left-column photo/about layout, after the About card, far above the items list. Users who scroll directly to the items section will see bid inputs and place bids without ever seeing the premium disclosure. This is financially material information — it should appear in or directly above the "Auction Items" section header (line 1086). — **severity: medium**

- **`approachNotes.startDate` not null-guarded before `parseISO`** — `pages/sales/[id].tsx:1567`. The outer render guard checks `approachNotes && approachNotes.notes` but not `approachNotes.startDate`. If `startDate` is absent, `parseISO(undefined)` returns `Invalid Date` and `format` throws a runtime error, crashing the approach notes section. Fix: `approachNotes.startDate && format(parseISO(approachNotes.startDate), ...)`. — **severity: low**

### Clean

- **Loading states** — Both pages use skeletons throughout; feed, sale detail, search all show loaders correctly.
- **Feed error state** — index.tsx handles `isError` with a centered error card and working Retry button.
- **Sale 404 and 429 error states** — sales/[id].tsx differentiates "Sale not found" vs "Too many requests" with distinct copy and a back link.
- **Empty states** — All item lists, search results, and no-sales scenarios have EmptyState components with icon, heading, and subtext.
- **No console.log in render paths** — Production-visible logging only in error catch blocks; acceptable.
- **SSR safety** — `localStorage` access in index.tsx is properly guarded (`typeof window !== 'undefined'` inside `useEffect`). `window.open` in the Maps button is inside an onClick handler (client-only) — no SSR risk.
- **Alt text** — All flagged `<img>` tags were verified: index.tsx line 453 uses `alt={item.title}`, sales/[id].tsx uses `alt={Sale photo N}`, `alt={Thumbnail N}`, and `alt={item.title}` — all present and descriptive.
- **Dark mode pairing** — Spot-checked bg/text classes throughout both files; all use paired `dark:` variants consistently.
- **No hardcoded placeholder copy** — "placeholder" string hits were input placeholders (correct usage), not rendered UI text.
- **UGC photos and approach notes** — Both sections are correctly gated with existence checks; no risk of rendering empty sections.

### Recommended Fixes

1. **(Medium)** Add `isError` to the search `useQuery` destructure in index.tsx and render an error message (e.g., "Search unavailable — try again") in the search results section when `isError` is true.

2. **(Medium)** Gate "Save This Search" button behind `user`: `{user && searchQuery && (<button ...>)}`. Show a "Sign in to save searches" link instead for unauthenticated users.

3. **(Medium)** Add `aria-label="Search sales by title, city, or keyword"` to the homepage search input. Add `aria-pressed={dateFilter === f}` to each date filter button.

4. **(Medium)** Fix OG meta double-render in sales/[id].tsx: the main `return` block should render `{ogHead}` directly rather than re-evaluating the SSR-vs-CSR conditional against `ogHead` and `saleForOGMeta`.

5. **(Medium)** Move the Buyer's Premium disclosure banner to immediately above or inside the Items section header (line ~1086), not the photo/about column. Alternatively add a second inline callout near the bid inputs.

6. **(Low)** Guard `approachNotes.startDate` with a null check before calling `parseISO` at line 1567.

7. **(Low)** Add a `pins.length > 0` guard around the SaleMap in index.tsx to avoid rendering an empty 220px map container when no sales have coordinates.
